# RFC 0001 — OSSP: OpenSocket Session Protocol

- **Status:** Draft
- **Date:** 2026-10-06
- **Scope:** Wire + persistence protocol between `opensocketd` and its clients
  (companion app, web PWA, CLI). Harness-facing translation is out of scope here;
  adapters map harness events onto OSSP.

---

## 0. Summary

OSSP is a small, event-sourced protocol. A session is an append-only sequence of
typed, JSON envelopes. Clients render; the daemon persists, fans out, and
translates from whatever harness produced the work. There is no provider concept
in the protocol (see RFC 0001 §6, R4).

## 1. Terminology

- **daemon** — `opensocketd`; owns sessions, storage, auth, fan-out.
- **client** — anything speaking OSSP: mobile app, web PWA, CLI.
- **harness** — an agent engine (opencode, pi, builtin) behind an adapter.
- **session** — one working thread in a workspace: `sess_<id>`.
- **envelope** — the only wire unit: one JSON object per event or request.

## 2. Envelope

Every message on the wire and every line in `events.jsonl` is one envelope:

```json
{
  "v": 1,
  "id": "evt_01JZZ...",
  "ts": "2026-10-06T12:00:00.000Z",
  "sessionId": "sess_01JZZ...",
  "seq": 42,
  "type": "message.delta",
  "payload": { }
}
```

| Field      | Type    | Notes                                                   |
|------------|---------|---------------------------------------------------------|
| `v`        | int     | Protocol version, currently `1`.                        |
| `id`       | string  | Unique message id (`evt_`/`req_` prefix + ULID/UUID).   |
| `ts`       | string  | RFC 3339 UTC.                                           |
| `sessionId`| string  | Owning session.                                         |
| `seq`      | int     | Monotonic per session. A gap means loss → resync.       |
| `type`     | string  | `domain.verb`, namespaced; see §4 and §5.               |
| `payload`  | object  | Shape depends on `type`. Unknown fields are ignored.    |

Requests use the same envelope with `type` from §5; the daemon replies with an
envelope of type `ok` or `error` whose payload echoes `reqId`.

## 3. Transport binding

- **Preferred:** one WebSocket per client (`/ws`). Both directions flow; events
  push out, requests go in. Authentication is the first message —
  `{"type":"hello","payload":{"token":<device token>}}` — after which the
  daemon replies `ok` (with `via`) and accepts request envelopes; a bad token
  closes the socket with code 4003. Tokens never appear in URLs.
- **Fallback:** HTTP — `GET /sse/<sessionId>` for the event stream (SSE),
  `POST /api/...` for requests. SSE `id:` carries `seq`; `Last-Event-Id`
  triggers resync.
- **Reconnect:** client sends `session.resume` (or `Last-Event-Id`). Daemon
  answers with a **snapshot** (§7) followed by the tail after `snapshot.lastSeq`.

## 4. Events (daemon → client)

| `type`                | Payload fields                                                   |
|-----------------------|------------------------------------------------------------------|
| `session.started`     | `workspace`, `harness`, `model?`, `resumeOf?`, `remoteSessionId?` |
| `session.updated`     | `name?`, `archived?` (user-facing metadata; additive) |
| `message.delta`       | `messageId`, `role`, `text`                                      |
| `message.completed`   | `messageId`, `role?`, `text`, `stopReason?`                      |
| `tool.call`           | `toolId`, `name`, `argsSummary`, `status`, `detail?`             |
| `tool.result`         | `toolId`, `summary`, `detail?`, `isError?`                       |
| `permission.request`  | `requestId`, `tool`, `argsSummary`, `riskHints?[]`               |
| `permission.resolved` | `requestId`, `decision`, `scope`                                 |
| `diff`                | `path`, `hunks[]`, `applyState?`                                 |
| `todo.updated`        | `items[]` (`id`, `text`, `state: pending|done`)                  |
| `usage`               | `tokensIn`, `tokensOut`, `costEstimate?`, `annotations?`         |
| `status`              | `state`: `thinking\|running\|awaiting_permission\|idle\|error`   |
| `error`               | `code`, `message`, `retryable?`                                  |
| `ok`                  | reply to a request: `reqId`, plus request-specific result fields |

Notes:

- Deltas join client-side into messages; `message.completed` is authoritative and
  replaces any joined text.
- `diff.hunks[]` entries: `{ kind: "add"|"del"|"context", text, oldLine?, newLine? }`.
- `usage.annotations` is an open map for optional harness-reported model metadata
  (pricing, context window). OSSP never interprets it (R4).

## 5. Requests (client → daemon)

| `type`               | Payload                                                  |
|----------------------|----------------------------------------------------------|
| `session.create`     | `workspace`, `harness`, `model?`                         |
| `session.resume`     | `sessionId`, `afterSeq?`                                 |
| `session.list`       | —                                                        |
| `prompt.send`        | `sessionId`, `text`, `attachmentIds?[]`                  |
| `interrupt`          | `sessionId`                                              |
| `permission.respond` | `sessionId`, `requestId`, `decision`: `allow_once\|allow_session\|deny` |
| `harness.list`       | —                                                        |
| `model.list`         | `harness` — models are opaque, harness-reported descriptors |
| `file.list`          | `sessionId`, `path?` — read-only                         |
| `file.read`          | `sessionId`, `path` — read-only                          |

`attachment.upload` is an HTTP `POST` (multipart) outside the envelope; it
returns `attachmentIds` for use in `prompt.send`.

## 6. Rules

- **R1 — Additive only.** New event/request types and payload fields may be
  added; existing ones never change meaning. Clients MUST ignore unknown `type`s
  and unknown fields.
- **R2 — Replay = fold.** `events.jsonl` is the source of truth: one envelope per
  line, ordered by `seq`. A client that folds the stream gets the same state as
  the daemon's snapshot.
- **R3 — Approvals are first-class.** A `permission.request` blocks the harness
  until `permission.respond` (or a policy resolves it). Harnesses that can
  gate themselves do so via a daemon-supplied hook — pi loads the
  `opensocket-approval` extension, which asks the daemon on every `tool_call`
  and blocks on deny/timeout. Harnesses with no gate at all get an explicit
  daemon-side policy (auto-deny by default; allowlist per workspace).
- **R4 — No provider concept.** Models are opaque harness-reported descriptors
  (`model.list(harness)`). Richer metadata travels only as `annotations` maps;
  nothing outside the harness interprets them.
- **R5 — No secrets on the wire.** API keys never appear in envelopes; auth is
  transport-level (device token + tailnet identity), not payload-level.

## 7. Snapshot

Reply to `session.resume` (and to WS join):

```json
{
  "type": "snapshot",
  "payload": {
    "meta": { "sessionId": "...", "workspace": "...", "harness": "...", "model": "..." },
    "messages": [ { "messageId": "...", "role": "...", "text": "..." } ],
    "tools":    [ { "toolId": "...", "name": "...", "status": "..." } ],
    "todos":    [ { "id": "...", "text": "...", "state": "..." } ],
    "usage":    { "tokensIn": 0, "tokensOut": 0 },
    "lastSeq":  42
  }
}
```

After the snapshot, the daemon streams the tail (`seq > lastSeq`). `snapshot`
is a transport artifact: it is **not** written to `events.jsonl`.

## 8. Security invariants

- The daemon fronts all auth (per-device tokens, plus optional proxy-provided
  identity such as Tailscale WhoIS headers when the user fronts it with
  `tailscale serve`). Clients never talk to harnesses directly.
- Workspaces are daemon-scoped roots; `file.list`/`file.read` resolve inside the
  session root and reject traversal.
- `permission.respond` is accepted only from paired devices of the session owner.
